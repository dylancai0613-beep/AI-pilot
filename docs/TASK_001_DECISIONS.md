# 任务 001：已确认实施决策

本文用于补充 `automation/tasks/001-build-mvp.md` 中未明确的实现细节。

Codex 必须读取本文件，但不得修改本文件。

## 1. 部署结构

采用单容器结构：

- FastAPI 提供后端接口；
- FastAPI 同时提供 frontend 目录中的静态网页；
- Docker Compose 服务名称固定为 `app`；
- 对外端口固定为 `8000`；
- Dockerfile 放在 `backend/Dockerfile`。

不建立独立前端容器。

## 2. 支持范围

必须支持以下四个城市之间所有不同城市组合：

- 广州
- 深圳
- 佛山
- 东莞

正向和反向路线使用相同的模拟数据。

## 4. 金额规则

- 高铁总价 = 单人票价 × 出行人数；
- 长途汽车总价 = 单人票价 × 出行人数；
- 网约车总价不随人数变化；
- 人均价格 = 总价 ÷ 出行人数；
- 金额保留两位小数；
- JSON 中金额使用数字，不使用带人民币符号的字符串。

## 5. 标签规则

每个方案必须包含 `tag` 字段。

- 当前总价最低的方案标记为 `最省钱`；
- 当前耗时最短的方案标记为 `最快`；
- 网约车在人数大于等于 3 时标记为 `多人更划算`；
- 如果某个方案没有符合条件的标签，`tag` 返回空字符串；
- 如果同一个方案同时符合多个标签，优先级为：
  1. 最省钱
  2. 最快
  3. 多人更划算

首版不处理并列情况，模拟数据应避免产生并列。

## 6. 错误响应

业务校验错误统一返回 HTTP 400。

使用 FastAPI 默认错误结构：

{
  "detail": "具体错误说明"
}

至少包含：

- 不支持的城市；
- 出发城市和目的城市相同；
- 人数小于 1；
- 人数大于 4；
- 人数不是整数。

## 7. 测试方式

Pytest 在 Docker 容器中运行。

固定验收命令：

docker compose up --build -d
docker compose ps
docker compose exec app pytest -q

健康检查：

Invoke-RestMethod http://127.0.0.1:8000/health

首页检查：

Invoke-WebRequest http://127.0.0.1:8000/

停止：

docker compose down
